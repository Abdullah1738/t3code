# Thread output redaction

`ThreadRedaction` is the sanctioned exception to event immutability: removing a credential from the visible item is ineffective while replay can restore it. It rewrites thread history and projections on the server's writer connection and appends a content-free audit event through the shared live sink. Item revisions advance, and shared clients purge persisted snapshots and refetch. Run forks and shared provider-session bindings expose content through independent thread cursors, so every dependent reader receives its own audit event and purges its cached projection. Running turns and background work in the source or dependent forks must stop first. Required item and native transcript structure remains intact; incompatible content collisions are refused before mutation.

Maintenance covers the live database, archive, normally readonly base and readonly replica. The exporter must stop and confirm its worker exited, and snapshot, writer and log barriers stay held through cleanup. Temporary write access and connection settings are restored before releasing the writer. The writer enables and restores `fullfsync` as well as FULL synchronization so the pending marker reaches durable storage on macOS before file mutations. `secure_delete` overwrites cells freed by the rewrite, but contiguous byte scans cannot prove erasure of fragmented overflow residue: full verification requires explicit `compact:true` to VACUUM every store and successful WAL truncation. Existing readers can prevent that proof. Attached WAL databases do not provide cross-file power-loss atomicity, and files cannot join their transaction. A durable, content-free pending marker prevents the exporter from republishing an incomplete operation. Recovery strings stay only in the original service's memory; after a restart, incomplete work requires explicit maintenance recovery. Cleanup failures retain recovery state until cleanup succeeds.

Claude session inventory includes nested subagent and workflow transcripts; Codex includes active and archived rollouts. Only owning-thread output and provider bindings contribute new needles; dependent forks are swept for those known copies. Provider files use same-directory fsync/rename, mode preservation and concurrent-write checks. Duplicate JSON object keys and numbers that cannot round-trip without precision loss are refused before mutation. Invalid UTF-8 is refused during preparation; valid unrelated bytes remain exact. Matching accounts for decoded JSON values, escaping and timestamped provider log framing. Claude task discovery uses owning session and task IDs together; unmapped task ownership keeps verification incomplete. Provider and server trace buffers drain under maintenance barriers, and stale writes cannot repopulate scrubbed logs; refusal before content mutation preserves queued provider writes. Verification covers named local stores; unsupported providers, recall, backups, filesystem snapshots, SSD remapping and offline clients require their own coverage or removal workflows.

MCP maintenance permission requires an active owner browser approving full-access OAuth with `environment:maintain`; the one-use authorization code retains that approval binding and rechecks it at exchange. Ordinary pairing, pre-existing tokens and thread credentials gain no maintenance permission. The control route also requires `environment:maintain`.
