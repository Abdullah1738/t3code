# OpenCode plugins

`codemode-guard` refuses `execute` code containing a known never-settling Promise executor (empty, returning the resolver without calling it, or not referencing either callback). It replaces the entire call with an error directing the model to poll in separate calls, before any preceding tool calls run. Detection is conservative, not a general JavaScript termination proof; callback handoffs and uncertain executors are allowed. Denials include the session and at most 300 characters of code in `~/.local/share/opencode-plugins/codemode-guard.jsonl`. The mtime-cached `~/.config/opencode/codemode-guard.json` off switch is `{"mode":"off"}`; absent means enforced. This applies only to OpenCode's built-in Code Mode runtime, not native Claude/Codex/codex-cu, which do not expose that runtime. After merge and push to origin/main and Abdullah's go, run `zsh integrations/opencode-plugins/install.zsh`. It backs up replaced files as `.bak-<stamp>` and never restarts OpenCode; the plugin takes effect after the separately approved restart. `--dry-run` previews without writes or a push requirement; `--check` compares content without writes or network access (exit 1 for missing files or drift, reporting missing files as “not installed”). Stream-recovery carries an identical detector because it deploys independently; its fallback bounds running `execute` calls to 3 minutes for these waits and 20 minutes otherwise.

Tests: `bun test integrations/opencode-plugins` and `node --test integrations/stream-recovery/test/*.test.mjs` from the repo root.

This targets OpenCode 2.0.22's `ctx.tool.hook("execute.before", ...)` API and legacy global `plugin/` discovery, like the offbox gate. The watcher limits use its existing unchanged-tail clock (first observation or newest timestamp, whichever is later), once-a-minute scan, person/subagent exclusions, and two-minute direct-interrupt fallback; they are not a hard execution deadline.
