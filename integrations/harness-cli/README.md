# harness-cli

Keeps pinned, verified Claude Code and Codex CLIs for Robob. Each tool lives under
`~/.robob/harness-cli/<tool>/<version>/` (read-only, never overwritten). A `current`
symlink per tool is the `binaryPath` Robob's `claudeAgent`, `codex` and `codex-cu`
instances run. Promotion swaps that symlink atomically; rollback points it back at the
last known good version.

Stdlib Python only (`/opt/homebrew/bin/python3`). Source: this folder. Installed copy:
`~/.local/share/harness-cli` (evaluator installs it with `deploy.zsh harness-cli`).

## Commands

```sh
harness_cli.py discover                  # npm view both packages (exempt, read-only); records candidates
harness_cli.py stage <tool> <version>    # npm pack (exempt), sha512 vs npm, extract read-only
harness_cli.py canary <tool> <version>   # throwaway homes + 9router prompts + memory-off canary
harness_cli.py promote <tool> <version>  # canary-gated atomic switch of current
harness_cli.py rollback <tool>           # current -> lastKnownGood
harness_cli.py rotate-codex [--when-idle]
harness_cli.py status
harness_cli.py auto                      # the daily job (launchd 06:00 Dubai)
harness_cli.py --before-release          # flag: discover + stage + canary both; prints the pins
```

`<tool>` is `claude` or `codex`. Every step appends one line to
`~/.robob/harness-cli/records.jsonl` (tool, version, binary sha256, Robob build, harness-home
config hashes, result). State lives in `~/.robob/harness-cli/state.json`.

## Version rules

- npm's global `min-release-age=7` is bypassed only by `--min-release-age=0` on the
  Claude Code and Codex packages (standing exception, DECISIONS 6). `~/.npmrc` is never edited.
- Integrity: the tarball's sha512 must equal `npm view <pkg>@<v> dist.integrity`. A mismatch
  stops the stage and writes nothing.
- Minimums come from `apps/server/src/provider/model-manifest.json`: the driver minimum for
  each CLI, and each model's minimum (Haiku 5.5 needs Claude 2.1.293; Astra and Sol need Codex
  0.153). A version below one is refused before download.
- A staged version must report exactly the version it was staged as.
- Claude uses the native `@anthropic-ai/claude-code-darwin-arm64` binary, and Codex uses
  `@openai/codex@<v>-darwin-arm64`.

## Canary (every promotion)

Runs in a throwaway HOME, with homes generated by `harness-homes generate|check --home-root`
(card B1) and a loopback proxy that records every request body and forwards to 9router
(`127.0.0.1:20128`). The key comes from `NINEROUTER_KEY` and is never printed.

- Claude: two Opus turns in one session must replay the first response's signed thinking and
  explicitly report empty `input_transformations`; Haiku gets a separate prompt. The first
  turn solves counting and modular-arithmetic problems with adaptive thinking and max effort;
  the recorder verifies those settings reached the request. If no thinking comes back, one
  fresh-session retry is allowed for diagnostics, but the entire run stays **inconclusive**
  and cannot authorize promotion, even if the retry succeeds. Request
  `context_management` and `anthropic-beta` are recorded as diagnostics, not gates.
- Codex: `codex exec` runs Astra and Sol on the generated `codex` home and Terra on the
  generated `codex-cu` home. Sessions are not ephemeral.
- Memory-off (DECISIONS 15, hard requirement): Claude gets a seeded `MEMORY.md` with a canary
  word; the word must not appear in any request body. Codex must perform no memory work
  or send memory in the request. Codex 0.166.0 unconditionally opens/migrates
  `memories_1.sqlite`, even with memories disabled; the database and its WAL/SHM files
  alone are harmless. Its startup pipeline is separately gated by `features.memories`.
  The canary initializes disposable v1/v2 memory stores from the exact tagged migrations,
  then arms persistent SQLite triggers **before bootstrap** on jobs, extraction outputs,
  and consolidation progress. Any committed mutation remains visible even if a job or
  output is deleted between filesystem observations. Database identity, schema/triggers,
  migration checksums and the audit marker are verified after each invocation and at the end.
  A clean store has no audit events, no job/output rows, and only the initial zero-progress
  row. Unknown CLI schemas fail closed until their migrations/lifecycle are verified.
  A unique sentinel in seeded memory files checks the read path separately, and seeded-file
  hashes distinguish the baseline from pipeline writes. Both enabled read and write controls
  must fire, including audited job/output writes, fixture content and recorded extraction
  traffic; otherwise the canary fails closed. Disabled model invocations remain alive for
  at least 120 seconds (or the enabled control's observed latency, whichever is longer).
  The recorder accounts for every request, and file checks reject memory content changes
  and unknown artifacts. Source/lifecycle: Codex tag `rust-v0.166.0`, commit
  `6ff1e1ca3b30fc8b914720681fcf5fe62e95f856`, `state/src/runtime.rs`,
  `state/src/runtime/memories.rs`, and `memories/write/src/start.rs`.
- Any failure, or a missing memory check, means no promotion. The record shows why.
- Temporary macOS homes get their own disposable login keychain before either CLI runs. Tests
  stub keychain creation and use fake CLIs and a fake loopback upstream.

## Rotation rules

- **Claude:** promote changes `binaryPath` for new processes only. Existing queries keep their
  binary. No restart, so promotion is safe to run automatically.
- **Codex:** promotion marks `rotationPending`. Runtime rotation is unsupported here and the
  flag remains set, including with `autoRotateCodex: true`: a provider snapshot refresh does
  not drain or replace either shared app-server. Safe automatic rotation needs the standing OK,
  an established E7 snapshot contract, a five-minute idle gate, recreation of both `codex` and
  `codex-cu`, and verification of both launched binary versions. A release/restart is separate.

## Daily job

`launchd/com.ardud.harness-cli.plist` runs `harness_cli.py auto` at 06:00 Dubai:
discover, stage, canary, promote Claude when the canary passes. Codex stops at
"promoted, rotation pending" even when `autoRotateCodex` is on. Telegram notices use keys
`harness-cli:<tool>:<version>:<promoted|canary-failed|stopped>`; failed sends remain in the
pending outbox and are retried independently of discovery. The notice command is
`HARNESS_CLI_NOTIFY`, overridable for tests.

## Install

```sh
integrations/deploy.zsh harness-cli --with-agent   # evaluator step, after review and merge
integrations/harness-cli/install.zsh --check       # drift check, no write
```

Deploying does not stage or promote anything by itself. The first run happens at the first
06:00, or when the evaluator runs `harness_cli.py --before-release` for the release.

## Tests

```sh
cd integrations/harness-cli && /opt/homebrew/bin/python3 -m unittest discover -s tests -v
```

Every path lives in a temp dir; a fake `npm` answers `view` and `pack`; fake CLI binaries print
their version and "OK"; a fake proxy records bodies. Tests never touch `~/.robob`, `~/.claude`,
`~/.codex` or the network.
